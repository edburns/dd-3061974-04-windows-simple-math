## Section 8: Observations and Recommendations

### 8.1 What Worked Well

- **Manifest integrity:** `shepherd-task-25-given-list-run.json` made the final outcome and invocation contract directly reproducible.
- **Objective acceptance:** Both stages consistently used the repository-owned PowerShell runner and pinned CI rather than substituting proxy validation.
- **Serial dependency control:** [#3](https://github.com/edburns/dd-3061974-04-windows-simple-math/issues/3) started from the merged result of [#2](https://github.com/edburns/dd-3061974-04-windows-simple-math/issues/2), as required.
- **Review convergence:** Both CCRA sequences ended at zero actionable comments after three rounds.
- **Safe local recovery:** The shepherd did not delete or overwrite the colliding foreign worktree directory.
- **Control isolation:** With lesson propagation `off`, no campaign lesson was imported into the second task, preserving the experimental control condition.

### 8.2 What Could Improve

- The plan specified non-negative integers but not the numeric representation or maximum safe range. CCRA therefore had to discover both the Fibonacci `Int64` limit (`N=92`) and factorial limit (`N=20`) during review.
- PR descriptions copied implementation details that became stale after review fixes. This generated one additional actionable round on each PR.
- Review-thread mutation handling assumed a successful GraphQL response would immediately confirm resolution.
- Worktree naming was only PR-number scoped and collided with a directory from another repository.
- A GitHub tree API lookup embedded `experiment/shepherd-control` as a path segment without robust slash-ref handling.
- Token fields were absent from exported assistant messages, limiting cross-run cost comparisons to AIU checkpoints.

### 8.3 Actionable Recommendations

1. **Resolve numeric contracts in stage 10/20 artifacts.** Require implementation issues to state result representation and maximum safe inputs whenever arithmetic can overflow. For this campaign, explicitly state Fibonacci `0..92` and factorial `0..20` for `[long]`.
2. **Keep PR descriptions contract-focused.** Avoid pasting exact validation expressions or implementation snippets unless stage 40 also updates them whenever review fixes change behavior. Add a pre-review consistency check between documented ranges and code.
3. **Make worktree paths repository-unique.** Include repository short name plus PR number, and preflight both `Test-Path` and `git worktree list --porcelain` before creation.
4. **Make thread resolution idempotent.** After posting a reply, query current state, resolve only if needed, inspect GraphQL errors explicitly, and retry the mutation without reposting.
5. **Use ref-safe GitHub lookups.** Resolve a slash-containing branch to a commit SHA first, then call the tree endpoint by SHA.
6. **Export reproducible token counters.** Preserve per-call input/output/cache token fields in JSONL or add them to the final usage checkpoint so stage 50 can report both tokens and AIU.
7. **Record recovered-error counters.** Persist retries, failed shell calls, workflow approvals, and worktree-path fallbacks in the run manifest to avoid reconstructing them from narrative logs.

### 8.4 Control-Run Interpretation

This run demonstrates full convergence without lesson propagation: 2/2 tasks merged in 1h 04m 42s, using six CCRA rounds and 309.49724 local AIU. The second task still repeated the same broad class of numeric-range and PR-description consistency defects found during the first task. Because lesson propagation was intentionally disabled, that recurrence is useful control evidence rather than a campaign-process violation. A treatment run with campaign lessons enabled should be compared on whether those two defect classes disappear before CCRA, reducing initial comments, review rounds, and stage-40 AIU.
